# HyperNova AI팀 3주 학습 안내

## 진행 방식

이번 학습은 **주차별 미니 과제 1개를 완성하는 방식**으로 진행합니다. 

- **참고용 교보재:** 공통·팀별 강의 및 참고 자료 링크를 Notion에 모아 제공합니다.
- **개인 학습 기록:** 각자 Notion 학습 페이지를 만들고, 학습 내용·시도한 방법·결과·막힌 점을 정리합니다.
- **정기 모임:** 주 1회 고정 모임에서 진행 상황과 결과를 공유하고, 질문 및 리뷰를 진행합니다. 요일·시간은 별도 안내합니다.
- **과제 제출:** 매주 AI-study GitHub 저장소에 PR을 올립니다.
- **리뷰 요청:** 매번 운영자를 Reviewer로 지정하고, PR 본문에도 운영자 계정을 멘션합니다. 계정은 별도 안내합니다.
- **완료 기준:** 결과물 제출과 설명, 리뷰 의견 반영까지 완료해야 해당 주차 과제가 끝납니다.

### GitHub와 Notion의 역할

| 구분 | 남길 내용 |
| --- | --- |
| **GitHub** | 완성 코드, 실행에 필요한 설정·의존성, 실행 설명, 결과 영상·스크린샷, 해당 과제의 정책 파일 |
| **Notion** | 참고한 교보재, 학습 과정, 실험·학습 로그, 오류와 해결 과정, 다음 할 일, PR 링크 |

Notion은 강의 내용을 전부 필사하는 용도가 아닙니다. **무엇을 시도했고, 어떤 결과가 나왔으며, 어디에서 막혔는지**가 보이도록 기록합니다. 최종 실행에 필요한 설정은 로그와 구분하여 GitHub에도 남깁니다.

### GitHub 제출 위치

```
AIstudy/
├── Week1/
│   └── 본인이름/
├── Week2/
│   └── 본인이름/
└── Week3/
    └── 본인이름/
```

- 매주 개인 작업 브랜치에서 작업하고, 본인 폴더의 변경 사항을 PR로 제출합니다.
- 기존 주차의 코드를 활용했다면 해당 위치를 명시하고, 이번 주차의 변경 사항을 설명합니다.
- 가상환경 폴더·캐시·불필요한 중간 파일은 업로드하지 않습니다.
- 영상·정책 등 큰 파일의 업로드 방식은 저장소 운영 기준에 맞춰 별도 안내합니다. 해당 주차 README와 PR에서 결과물에 접근할 수 있어야 합니다.

### 매주 PR에 포함할 내용

1. **과제 목표와 구현 내용**
2. **본인이 작성하거나 변경한 부분** — 제공 코드와 구분
3. **실행 환경과 실행 방법**
4. **결과물 및 실행 확인 결과**
5. **개인 Notion 학습 페이지 링크**
6. **미완료 항목 또는 질문** — 있는 경우

아래 기한은 **1차 PR 제출 기한**입니다. 리뷰 반영 기한은 리뷰 시 안내합니다. 기한까지 해결하지 못한 경우에도 시도한 코드와 오류·진행 상황을 제출하고, 모임에서 해결 후 보완합니다.

## 1주차 — 공통: GitHub 협업과 실행 환경 관리

**기한: 2026년 9월 20일**

### 목표

간단한 로봇 주행 데이터를 **pandas로 분석하고 Matplotlib으로 시각화**합니다. Python 가상환경과 의존성을 관리하고, 터미널에서 Git을 사용해 PR 제출과 리뷰 반영까지 경험합니다.

### 제공 자료

- AI-study GitHub 저장소 주소와 리뷰어 계정
- 실습용 주행 데이터 (AI-study 레포 내부)
- Git, venv, pandas, Matplotlib 관련 교보재 — Notion에 공유

### 1. 저장소와 작업 환경 준비

1. 터미널에서 HyperNova 저장소를 `git clone`합니다.
2. 개인 작업 브랜치 `aistudy/week1/본인ID`를 만듭니다.
3. `AI-study/Week1/본인이름/` 폴더에서 작업합니다.
4. Python `venv`로 가상환경을 만들고 pandas와 Matplotlib을 설치합니다.
5. `.gitignore`를 작성해 가상환경과 캐시가 커밋되지 않도록 합니다.

### 2. 데이터 분석과 그래프 작성

실습용 CSV 파일은 **HyperNova GitHub 저장소에 미리 제공**합니다. 1번에서 `git clone`한 저장소의 CSV 파일을 본인 작업 폴더에 복사해 사용합니다. 원본 파일은 수정하지 않습니다.

CSV에는 시간(`time_s`, 초)과 로봇의 속도(`speed_mps`, m/s)가 기록되어 있습니다.

#### 구현할 기능

- **pandas**로 CSV 파일을 읽습니다.
- 아래 정보를 계산해 터미널에 출력합니다.
    - 데이터 개수
    - 기록 구간 길이: 마지막 시간 − 첫 시간
    - 평균 속도: 기록된 속도의 산술평균
    - 최대 속도
- **Matplotlib**으로 시간에 따른 속도 변화를 선 그래프로 표현합니다.
- 그래프에 제목과 축 이름·단위를 표시하고 PNG 파일로 저장합니다.

그래프의 색상과 디자인은 자유입니다.

#### 기대 결과

| 항목 | 결과 |
| --- | --- |
| 데이터 개수 | 10개 |
| 기록 구간 길이 | 9초 |
| 평균 속도 | 0.20 m/s |
| 최대 속도 | 0.40 m/s |

### 3. 의존성 관리와 재실행

1. 사용한 패키지 버전을 포함한 `requirements.txt`를 만듭니다.
2. 기존 환경과 별개로 **빈 가상환경을 하나 더 생성**합니다.
3. 새 환경에서 패키지 설치 전 코드를 실행해보고, 어떤 오류가 발생하는지 확인합니다.
4. `requirements.txt`를 사용해 패키지를 설치합니다.
5. 코드를 다시 실행해 같은 분석 결과와 그래프가 생성되는지 확인합니다.

이 과정에서 **실제로 실행되는 Python의 위치**, **패키지가 설치되는 환경**, **직접 설치한 패키지 외에 함께 설치된 의존성**을 확인해봅니다.

### 4. GitHub PR 제출과 리뷰 반영

Git 작업은 터미널에서 진행하고, PR 작성과 리뷰는 GitHub 웹에서 진행합니다.

1. `git status`와 `git diff`로 변경 사항을 확인합니다.
2. 제출할 파일을 선택해 커밋하고 개인 브랜치를 push합니다.
3. HyperNova 저장소에 PR을 작성합니다.
    - 제목: `[Week1] 본인이름 - 주행 데이터 분석`
    - 본문: 무엇을 구현했고 어떻게 실행·확인했는지 설명
4. 운영자를 **Reviewer로 지정**하고 본문에도 멘션합니다.
5. 리뷰 의견에 따라 수정하고, **같은 브랜치에 추가 커밋을 push**합니다.
6. 리뷰 댓글에 반영 내용을 답변하고 재검토를 요청합니다.

병합은 운영자가 진행합니다.

### GitHub 제출물

`AI-study/Week1/본인이름/` 아래에 다음을 제출합니다.

- Python 분석 코드
- 입력 CSV 파일
- 결과 그래프 PNG
- `requirements.txt`
- `.gitignore`

**가상환경 폴더와 캐시는 제출하지 않습니다.** README 작성은 자유이며, 학습 과정은 개인 Notion 페이지에 편한 방식으로 정리합니다.

### 완료 기준

- pandas와 Matplotlib을 모두 사용했다.
- 분석 결과가 기대 수치와 일치하고 그래프가 저장된다.
- 새 가상환경에 의존성을 설치해 재실행했다.
- PR에 실행·확인 방법을 설명하고 운영자에게 리뷰를 요청했다.
- 리뷰 의견을 반영한 추가 커밋과 답변을 남겼다.

## 3주차 — 팀별 핵심 기능 적용

**기한: 2026년 10월 4일**

### 인지팀: FAST-LIO2 위치추정과 RViz 시각화

#### 과제

3D LiDAR와 IMU가 장착된 TurtleBot 시뮬레이션에서 센서 데이터를 받아 FAST-LIO2로 odometry와 지도를 추정하고, RViz에 표시합니다. 로봇을 이동시키면서 추정 결과가 갱신되는 것을 확인합니다.

```
3D LiDAR + IMU → FAST-LIO2 → 추정 odometry·지도 → RViz
```

#### 제공되는 것

- 3D LiDAR·IMU의 장착 위치가 정의된 TurtleBot URDF 및 관련 자산
- 센서 데이터가 실제로 생성·발행되는 시뮬레이션 설정
- FAST-LIO2 입력과 호환되는 센서 데이터 형식 및 시간 설정
- 사용할 FAST-LIO2 구현·버전과 기본 설정 예제
- 센서 토픽, 좌표계, FAST-LIO2, RViz 관련 교보재

제공 환경은 운영자가 센서 입력과 FAST-LIO2 실행 가능 여부를 사전에 검증합니다.

#### GitHub 제출물

- FAST-LIO2 연결·실행에 사용한 코드와 launch·설정 파일
- 센서 토픽·좌표계 및 실행 방법이 포함된 `README.md`
- **RViz에서 추정 궤적과 지도가 보이는 스크린샷**
- **로봇 이동에 따라 추정 궤적·지도가 갱신되는 영상**

#### 완료 시 설명할 내용

FAST-LIO2의 입력과 출력, 기존 TurtleBot odometry와 FAST-LIO2가 추정한 odometry의 차이를 설명합니다. 이번 과제는 추정 결과 확인까지이며, 이를 Nav2에 다시 연결하는 작업은 선택 확장으로 둡니다.

### 보행팀: 학습한 Go2 보행 정책을 미로에 적용

#### 과제

Isaac Lab과 RSL-RL의 기존 Go2 보행 예제를 활용해 정책을 학습하고, 실행용 정책을 저장합니다. 이를 2주차 미로 환경에 적용하여 teleop으로 주행합니다.

목표는 **사용자의 속도 명령에 따라 걷는 정책을 학습하고 적용하는 것**입니다. 미로 경로를 스스로 찾는 정책 학습은 이번 과제에 포함하지 않습니다.

#### 제공되는 것

- 2주차 실행 환경과 호환되는 Go2 학습 예제 및 기본 설정
- 강화학습 기초, Isaac Lab, RSL-RL 관련 교보재
- 정책 학습·저장·내보내기·불러오기 예제
- 학습 정책을 기존 teleop에 연결하는 실행 예제
- GPU 사용 환경과 학습 시간 안내
- 제출해야 할 실행용 `.pt` 형식 안내

#### GitHub 제출물

- **본인이 학습하여 내보낸 실행용 `.pt` 정책 파일**
- 정책 실행에 필요한 환경·입출력 설정과 변경 코드
- 학습 및 정책 적용·실행 방법을 정리한 `README.md`
- **본인 정책을 적용한 Go2가 2주차 미로에서 teleop으로 주행하는 영상**

#### Notion에 남길 학습 기록

- 사용한 학습 설정과 본인이 변경한 항목
- 학습 실행 기록과 보상 등 주요 그래프
- 학습·적용 과정에서 발생한 문제와 해결 시도
- 제공된 정책과 본인 정책의 동작 차이 및 관찰 내용

#### 완료 시 설명할 내용

학습에 사용한 관측·행동·보상의 기본 역할, 저장한 정책의 적용 방법, teleop 명령이 정책에 전달되는 흐름을 설명합니다. 성능 향상 자체보다 **직접 학습하고, 저장하고, 다시 불러와 실행하는 과정**을 확인합니다.
